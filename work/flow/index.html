01 / PROBLEM

预约不是一个按钮，而是一条业务链。

用户需要找到服务、选择时间、确认信息、查看订单和再次预约；商家同时要管理预约状态、服务配置和会员信息。FLOW 用一套小程序 + 商家后台的结构把两端流程连接起来。

02 / USER FLOW

把关键状态提前定义。

预约类产品最容易在“已提交、待确认、已确认、已完成、已取消”这些状态上出问题。先定义状态，再设计页面，避免前端界面与后台处理逻辑互相冲突。

01选择服务
02选择日期
03确认信息
04订单状态
05再次预约

商家后台

预约列表按日期与状态筛选；服务项目维护价格、时长与可预约时间；用户信息与订单记录关联，方便后续会员运营。

数据边界

概念方案将服务、时间段、预约、用户、会员权益和订单拆分为独立数据对象，减少后续功能扩展时的耦合。
